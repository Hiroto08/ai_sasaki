# 15分余興 進行台本｜佐々木社長 就任お祝い会

- 想定：200名規模・会場貸切・**ご本人在席**
- 持ち時間：15分（転換込み）
- 使うもの：スクリーン1面、司会マイク2本、参加者のスマホ、QR掲示

---

## 0. 設計方針：「ライブ感は演出、中身は全部仕込み済み」

出たとこ勝負をなくす原則は一つです。

> **本番でAIに"考えさせない"。本番は、確認済みの原稿を"再生"する。**

ステージ画面の **📝台本モード** をONにすると、AIを一切呼ばずに事前確認済みの回答を
1文字ずつ表示します（＝生成失敗・遅延・変な回答・API障害のリスクがすべてゼロ）。
会場からは「いま考えて喋っている」ようにしか見えません。

| 要素 | 出たとこ勝負版 | **安定版（本書）** |
|---|---|---|
| AIの回答 | 本番で生成（内容も速度も運任せ） | **前日に生成→確認→台本に保存→本番は再生** |
| 会場の質問 | その場で自由入力 | **仕込み3問＋自由枠1問**（自由枠は失敗しても笑いになる場所に置く） |
| 思い出の投稿 | 15分枠の中で集める | **受付〜歓談中に集めておく**（枠内は「まだの方どうぞ」） |
| フィナーレ | 本番でその場生成 | **直前の休憩中に生成＆幹事確認 → 再生** |
| 尺 | 進行しだい | **1分単位のキューシート＋画面内タイマー** |

**それでも"生"の要素は残す**：会場から届く声のティッカーは本物がリアルタイムで流れます。
ここだけは仕込めない、かつ失敗しても困らない。だから安全にライブ感が出ます。

## 1. 事前準備のタイムライン

### 【3日前】素材づくり
- [ ] ステージ画面を開き、**台本モードOFF**でプリセット①〜⑧を全部押す
- [ ] 気に入った回答が出たら **💾「いまの回答を台本に保存」** を押す
      （気に入らなければもう一度押して引き直す ＝ 良い回答だけを採用できる）
- [ ] 全部そろったら **📝台本モードをON**にして、もう一度①〜⑧を通しで再生確認
- [ ] `data/content/stage_script.json` を **git commit**（Cloud Run利用時はこれを再デプロイ）

> 💡 これで①〜⑧の回答は「幹事が読んで面白いと確認済みの文」に固定されます。

### 【3日前】ご本人パートの仕込み
- [ ] ご本人に**3つの質問**へ回答してもらい、書き起こす（第2幕で使用）
- [ ] 同じ質問をAIに投げ、回答を保存 → A/B比較スライドを作って**印刷もしておく**

### 【前日】通しリハーサル（30分）
- [ ] 15分を実際に計測して通す（画面内タイマーを使用）
- [ ] 思い出を10件テスト投稿 → ティッカー表示 → フィナーレ生成まで確認
- [ ] **リハ後に投稿を全消去**（下記コマンド）
- [ ] プロジェクタで文字サイズ・赤い覇気の見え方を確認（`+`/`-`キーで調整）

```bash
# リハーサルで入れたテスト投稿を消す（TOKENは/api/verifyで取得した値）
curl -X DELETE https://あなたのURL/api/memories -H "authorization: Bearer $TOKEN"
```

### 【当日・開会〜歓談中】★ここが安定化の肝
- [ ] **受付でQRを配布**し、「佐々木さんの思い出を送ってください」と依頼
- [ ] 歓談中に投稿が集まる（目標100件以上）
- [ ] **余興の1つ前の演目中に**、幹事がフィナーレを生成 → 内容を確認 → 💾保存
- [ ] 台本モードがONであることを最終確認

> これで15分枠に入る時点で、**フィナーレの原稿まで確定済み**になります。

## 3. 「これだけは守る」5箇条

1. **台本モードは本番中ONのまま**。触らない
2. **自由入力は仕込み文の貼り付けのみ**。その場で考えて打たない（誤字・変な回答の元）
3. **フィナーレ前に必ずBGMを絞る**。音が鳴っていると感動しない
4. **フィナーレ中、司会は一言も喋らない**。20秒の沈黙に耐える
5. **最後は必ずご本人にマイクを返す**。AIで終わらせない

## 4. リスクと対策（安定版）

| リスク | 対策 | 残存リスク |
|---|---|---|
| AI生成の失敗・遅延 | **台本モードで本番はAIを呼ばない** | ほぼゼロ |
| 変な回答が出る | 前日に幹事が確認した文のみ採用 | ゼロ |
| 通信が落ちる | 台本モードはネット不要で再生可能。投稿ティッカーが止まるだけ | 軽微 |
| 投稿が集まらない | 受付から集め始める＋幹事5名が先に投稿。**0件でもフィナーレは成立する設計** | 軽微 |
| 不適切な投稿 | NGワードフィルタ＋**生の投稿は流れるティッカーのみ**。大文字表示は確認済みの原稿だけ。危なければ📮OFFで即回避 | 軽微 |
| 尺オーバー | 画面内タイマー＋調整弁（第2幕1問カット） | 軽微 |
| ご本人が乗ってくれない | 第2幕は「本人が話さなくても成立」する構成（司会が回す） | 軽微 |
| プロジェクタが映らない | 会場入り時に接続確認。最悪、司会がフィナーレ原稿を読み上げる（印刷を持つ） | 軽微 |

**バックアップとして必ず紙で持つもの**：フィナーレ原稿、A/B比較の3問、仕込み質問文。

## 5. なぜこれが有名人枠に勝てるのか（幹事説明用）

| 観点 | 有名人枠 | この企画 |
|---|---|---|
| 参加 | 200人は「観客」 | **200人全員が「作り手」** |
| 固有性 | 名前を差し替えれば誰にでも使える祝辞 | **佐々木さんの名前しか入らない** |
| 主役 | 有名人が目立つ | **徹底してご本人を立てる構造** |
| 残るもの | 「豪華だったね」 | **200人分の"佐々木さん評"がデータで残り、ご本人への贈り物になる** |
| コスト | 出演料 | **1,000円未満** |

**順番の交渉**：可能なら**有名人枠の後**に置く。華やか→手作りの温かさ、の順で感情が上がるため。

## 6. 設定チェックリスト

- [ ] `.env`：`PASSPHRASE` をお祝い会用に変更、`MAX_TURNS=20`、`MAX_PER_MIN=10`
- [ ] `data/config.json`：`eventMode.memoryEnabled` が **true**
- [ ] `data/content/stage_script.json`：`enabled` が **true**、`answers` が9件そろっている
- [ ] `MODEL=gemini-2.5-flash`
- [ ] 写真を使う場合は `public/avatar.png` を配置（**要ご本人了承**）
- [ ] 辛口モードの内輪ネタ（`greetings.json` の `spicyPunch`）は、いじられる本人の了承後に設定
