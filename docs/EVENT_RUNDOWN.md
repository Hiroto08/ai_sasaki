# 15分余興 進行台本｜佐々木社長 就任お祝い会

- 想定：200名規模・会場貸切・**ご本人在席**
- 持ち時間：15分（転換込み）
- 使うもの：スクリーン1面、司会マイク2本、参加者のスマホ、QR掲示

---

## 0. 戦略：有名人には「豪華さ」で勝てない。勝てるのは「固有性」

別チームが有名人を呼ぶと聞いて張り合うなら、**同じ土俵に乗らないこと**が唯一の勝ち筋です。

| | 有名人枠 | 我々の枠 |
|---|---|---|
| 強み | 華やか・非日常・記念撮影 | **この200人にしか作れない** |
| 弱み | **佐々木さんを知らない**。祝辞は誰にでも言える内容 | 華やかさでは勝てない |
| 残るもの | 「豪華だったね」 | 「自分たちが作った」という記憶 |

有名人の祝辞は、極端に言えば**名前を差し替えれば誰にでも使える**。
我々が作るべきは、**佐々木さんの名前しか入らないもの**です。

### だから、こう組み立てる

> **AI社長は、最初は佐々木さんのことを何も知らない。**
> **それを、会場の200人が教えて育てる。**
> **最後、育ったAIが200人を代表してお祝いを述べる。**

AIが主役ではありません。**AIは200人の想いを届ける「器」**です。
有名人は「外から来て、祝って、帰る」。我々は「会場全員が、祝う側になる」。

そして構造上、**有名人枠の後に置いたほうが勝てます**（華やか→手作りの温かさ、の順で
感情が上がるため）。順番は幹事に交渉する価値があります。

## 1. タイムテーブル（15分）

| 時間 | パート | 見せ場 |
|---|---|---|
| 0:00–1:30 | **【起】掴み**「有名人、呼べませんでした」 | 自虐からのAI登場 |
| 1:30–3:30 | **【起】AIの限界を露呈** | 「好きな食べ物は？」に答えられない |
| 3:30–6:00 | **【承】200人がAIを育てる** | QRで一斉投稿、声が大画面に流れる |
| 6:00–9:30 | **【転】本人 vs AI 対決** | どっちが本物？ |
| 9:30–11:30 | **【転】辛口モード解禁** | 赤い覇気で笑いの緩急 |
| 11:30–14:00 | **【結】AI覚醒 → お祝い** ★クライマックス | 200人の声を織り込んだ祝辞 |
| 14:00–15:00 | **【結】ご本人へマイク** | 主役に返して締め |

## 2. 詳細台本

### 【0:00–1:30】掴み — 弱みを先に出して笑いに変える

> 司会：「さて、他のチームさんは、なんと**有名人**をお呼びになったそうです。
> （間）…我々は、**呼べませんでした。**」
>
> （会場：笑い）
>
> 司会：「その代わり、**佐々木社長ご本人**をお呼びしました。」
>
> （会場：ざわ…「本人いるじゃん」）
>
> 司会：「**もう一人の**、佐々木社長です。」 → **スクリーン切替、AI登場**

- スクリーンに `/stage.html` を投影 → プリセット**①登場のあいさつ**
- AI「本日はお招きいただきありがとうございます。私は公開情報だけでつくられた
  AIパロディ社長です。本物ではありませんが、サービス精神は本物です。」

**設計意図**：予算で負けていることを自分から言ってしまうと、以降それが武器になる。
「金はないが、手間はかけた」という構図を最初の30秒で作る。

### 【1:30–3:30】AIの限界を露呈させる ★重要

**ここでAIをわざと恥をかかせます。** これが後半の感動の伏線になります。

- 司会がプリセット**②【弱点】好きな食べ物は？** をクリック
- AI「…申し訳ありません。**それは公開情報にはありませんでした。**」
- 司会：「え、知らないんですか？」
- 続けて会場から2〜3問、あえて**答えられない質問**を振る
  - 「口癖は？」「部下からどう呼ばれてる？」「朝は何時に起きる？」
- AI「ニュース記事と決算説明会の資料しか読んでいないもので…」

> 司会：「…このAI、**佐々木さんの"実績"は知っているけど、"人柄"を何も知らない**んです。」

**設計意図**：AIの無力さ＝「公開情報だけでは、人は分からない」という事実の可視化。
これが「じゃあ誰が知っているのか？ → **この部屋の200人だ**」への転換点になる。

### 【3:30–6:00】200人がAIを育てる ★参加パート

> 司会：「そこで皆さんにお願いがあります。
> **皆さんが知っている佐々木さんを、このAIに教えてあげてください。**」

- スクリーンにQRと合言葉を大きく表示
- 参加者はアプリ内の **📮「佐々木さんへの『思い出』を送る」** ボタンから投稿
  - お題：「あなたが知っている佐々木さんを、ひとこと教えてください」
- 司会がステージ画面の **📮「声を表示」** をONにする
  → **届いた声が大画面を流れ始める**（件数もリアルタイム表示）

> 司会：「おお、来た来た！『会議で必ず現場の話を聞いてくれる』…いいですね。
> あ、『ゴルフの話になると急に饒舌』（笑）」

- 司会は流れてくる声を2〜3個ひろって読み上げる（ここが一番あたたまる）
- ご本人の照れる顔をカメラで抜く

**運営Tips**：目標は**100件以上**。「一人一つ、必ず送ってください」と明確に依頼する。
サクラとして幹事メンバー5人が最初に投稿しておくと、流れが生まれる。

### 【6:00–9:30】本人 vs AI「どっちが本物？」

**まだAIは"育つ前"**という設定を活かす。

#### 事前準備（前日まで）
1. ご本人に**3つの質問**へ回答してもらい書き起こす
2. 同じ質問をAIに投げて回答を保存（当日生成でも可）

#### 進行
> 司会：「AIはまだ皆さんの声を読み込んでいません。この状態で、本人に勝てるでしょうか？」

- A/B両方の回答をスクリーンに並べる
- **会場投票**：「Aだと思う人は拍手！」→「Bだと思う人は拍手！」（音量で判定・低リスク）
- 正解発表 → ご本人に一言もらう（ここが一番笑いが起きる）
- 3問繰り返す（1問80秒）

**どちらに転んでも成立する**：AIが勝てば「AIすごい」、負ければ「やっぱり本人にはかなわない」。
後者のほうが本命の展開なので、負けても慌てないこと。

### 【9:30–11:30】辛口モード解禁 — 緩急をつける

> 司会：「実はこのAI社長、**もう一つのモード**があります。…**辛口モード**！」

- ステージ画面の 🌶️ボタンをON → **アバターの周りに赤い覇気**
- 会場：どよめき
- プリセット**⑧【辛口】最近どう？** で会場をいじる

**内輪ネタ**：`data/content/greetings.json` の `spicyPunch` に一言を設定すると、
辛口モード後の最初の回答の前に2秒タメて決め台詞が出ます（デフォルトは非表示）。
※**いじられる本人の了承を取ってから**設定すること。

**設計意図**：ここで一度大きく笑わせて温度を上げ、次のフィナーレで一気に落とす。

### 【11:30–14:00】AI覚醒 → お祝い ★クライマックス

> 司会：「…では、そろそろ。AI社長に、**皆さんが送ってくださった声**を読んでもらいましょう。」

- 辛口モードを**OFFに戻す**（赤い覇気が消える＝空気が切り替わる。演出上とても重要）
- 司会が **🎉フィナーレ** ボタンをクリック
- 画面に「**皆さまの声を読んでいます…**」
- **数秒の沈黙**（ここで会場が静まる。BGMを絞ると尚よい）
- AIが、**会場から届いた実際のエピソードに具体的に触れながら**お祝いを述べる
  - 「『会議で必ず現場の話を最初に聞いてくれる』…この一文が、何度も出てきました」
  - 「私は決算資料しか読んでいませんでした。皆さまのお声で、はじめて本当のあなたを知りました」
  - 「ここから先の物語は、**本物のあなたにしか書けません**」

**これが有名人には絶対にできないこと**：200人の実名の想いを、その場で束ねて言葉にする。

### 【14:00–15:00】ご本人へ

- スクリーン暗転 → ご本人にマイク
- 「今日、皆さんが送ってくださった声は、後ほど全文お渡しします」と司会が添えると完璧
  （運営はステージPCで `GET /api/memories` を開いて保存しておく）

## 3. 有名人枠との差別化ポイント（幹事説明用）

| 観点 | 説明 |
|---|---|
| **参加率** | 有名人＝200人が「観客」。我々＝200人全員が「作り手」 |
| **固有性** | 祝辞の中身が、この会場でしか成立しない（名前の差し替えが不可能） |
| **主役の扱い** | 有名人は自分が目立つ。AIは徹底して佐々木さんを立てる構造 |
| **後に残る** | 200人分の"佐々木さん評"が文字データとして残り、ご本人への贈り物になる |
| **コスト** | 出演料ゼロ。API代1,000円未満 |

## 4. 当日の運用チェックリスト

### 機材・環境
- [ ] スクリーンに `/stage.html` を全画面表示（F11）
- [ ] **会場Wi-Fi**：200人同時接続に耐えるか事前確認。ステージPCは有線orテザリングで確保
- [ ] 音声読み上げは**使わない**（会場マイクと競合）
- [ ] フィナーレ前にBGMを絞る合図を音響担当と決めておく

### 設定
- [ ] `.env` の `PASSPHRASE` をお祝い会用に変更
- [ ] `MAX_TURNS=20` / `MAX_PER_MIN=10`（司会が連続操作するため）
- [ ] `data/config.json` の `eventMode.memoryEnabled` が **true** か確認
- [ ] `MODEL=gemini-2.5-flash`（速度重視）
- [ ] 写真を使う場合は `public/avatar.png` を配置（**要ご本人了承**）

### リハーサル（前日必須）
- [ ] 思い出を10件ほどテスト投稿 → ティッカー表示 → フィナーレ生成まで通す
- [ ] **リハ後に投稿を全消去**する
      （ステージ画面のコンソール、または `curl -X DELETE .../api/memories -H "authorization: Bearer <token>"`）
- [ ] 辛口モードの覇気がプロジェクタで見えるか（明るさ調整）
- [ ] 第2幕のA/B回答を紙に印刷（通信障害時のバックアップ）

### リスクと対策
| リスク | 対策 |
|---|---|
| 投稿が集まらない | 幹事5名が事前投稿。司会が「一人一つ必ず」と明確に依頼。0件でもフィナーレは成立する設計 |
| 不適切な投稿が出る | NGワードフィルタ実装済。生の投稿は**流れるティッカーでのみ**表示し、大文字表示はAI生成文（ガードレール通過後）に限定。危なければ「声を表示」をOFFにするだけで回避 |
| AI生成が失敗 | フィナーレは**APIが落ちても**集まった声を読み上げる形で自動フォールバック（検証済） |
| 会場Wi-Fiが落ちる | 参加パートを飛ばしても進行可能。その場合フィナーレは幹事の事前投稿分で実施 |
| 時間超過 | 第2幕を3問→2問で2分短縮できる（調整弁） |
