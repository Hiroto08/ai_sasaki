## 0. #3クイズの構成：A/Bはスライド、正解発表でアバターが登場

**回答の提示はスライド（文字）、正解発表でAI社長の動画を流します。**

| 段階 | 画面 | ねらい |
|---|---|---|
| ① 出題 | 設問のスライド | — |
| ② **A・Bの回答** | **2つを並べたスライド（文字のみ）** | **形式が完全に対称。答えが漏れない** |
| ③ 投票 | 同じスライドのまま | 見比べながら判断できる |
| ④ **正解発表** | ★**AI社長の動画**（20秒） | **アバターが「答え合わせの主役」として登場** |
| ⑤ 本人コメント | 動画を止めて、ご本人へ | 一番笑いが起きるところ |

### この構成の利点

1. **原理的に答えが漏れない。** A も B も同じスライドなので、形式による手がかりがゼロ
2. **並べて同時に見せられる。** 動画を順番に流すと200人が記憶で比較することになる。
   並べれば**その場で見比べられる**──クイズとしての成立度が根本的に上がる
3. **アバターの役割が上がる。** 回答を読む係ではなく、**正解を告げる存在**になる
4. **制作が軽い。** HeyGen動画は**7本**で済み、スライドは直前まで修正できる
5. **リズムが良い。**「文字（静）→ 投票（参加）→ 動画（払い）」が毎問繰り返される

### 必要な動画は7本

| # | 用途 | 本数 |
|---|---|---|
| #2 | 最初の挨拶 | 1本 |
| #3 | **正解発表**（各問1本） | **5本** |
| #4 | ループ用 | 1本 |
| | **合計** | **7本** |

## 1. プロンプトで作れる部分／作れない部分

**ここを取り違えると無駄な作業が発生します。**

| 要素 | 作り方 | プロンプト |
|---|---|---|
| **顔・表情・口の動き** | 8/20に撮影した本人の映像から**HeyGenが生成** | ❌ 使わない |
| **服装** | **8/20に本人が着ていた服がそのまま出ます** | ❌ 変えられない |
| **構図（バストアップ等）** | 8/20の撮影時の画角で決まる | ❌ 撮り方で決める |
| **背景** | 撮影後に**差し替え可能** | ✅ **プロンプトで生成** |
| **背景の動き**（#4ループ用） | 同上 | ✅ **プロンプトで生成** |
| **ネームプレート・テロップ** | 編集ソフトで後乗せ | ✅ デザイン指定 |

> 💡 つまり**プロンプトで作るのは「背景」**です。人物側は 8/20 の撮影条件で決まります。
> **§2 の撮影指示のほうが、ルックへの影響は大きい**と考えてください。

## 2. ルックの設計方針

### 狙い：#1とのギャップで笑わせる

| | ルック | 意図 |
|---|---|---|
| **#1 オープニング** | 暗い舞台・金のスーツ・爆発・お札 | 祭り。振り切る |
| **#2〜#4** | **落ち着いた企業スタジオ。真面目そのもの** | ★**ここを真面目に作るほど面白くなる** |

AIが大真面目な顔で就任会見のように喋る──**そのギャップが笑いになります**。
#2〜#4のルックは、**ふざけずに、信頼できる映像として作ってください。**

### トーン

- **落ち着き・信頼感・わずかな先進性**。派手な色や装飾は入れない
- **人物より背景を1〜2段暗く**する（200人の会場で人物が沈まないように）
- **中央は無地**にする（人物が立つ位置。模様があると視線が散る）

### ⚠️ 入れてはいけないもの

- **会社のロゴ・社名・ブランドカラーそのもの**
  → 本企画は**非公式のパロディ**です。公式コンテンツに見える要素は入れないでください
- 文字・透かし・人物・小物
  → 背景素材は**完全に無人・無文字**で生成します

## 3. 背景の生成プロンプト

画像生成AI（Midjourney / DALL·E / Ideogram など）または HeyGen の AI Video Generator で作ります。
**16:9・無人・無文字**が共通の条件です。

### 3-A　本命：企業スタジオ（★これを推奨）

```
a modern corporate broadcast studio background, completely empty,
no people, no text, no logos, deep navy and charcoal gradient wall,
soft horizontal light bars along the sides, subtle out-of-focus bokeh
light points in the far background, clean and minimal, cool neutral
lighting with a faint teal accent, shallow depth of field, slight
vignette, photorealistic, 16:9
```

**狙い**：ニュース番組・記者会見のような信頼感。中央が空いているので人物が映える。

### 3-B　先進的：抽象データ背景

```
an abstract dark navy background with very faint flowing data lines
and soft glowing particles, heavily out of focus, no people, no text,
no logos, elegant and calm, subtle teal accent glow, cinematic,
shallow depth of field, minimal, 16:9
```

**狙い**：「AI」であることをそれとなく示す。**ただしやりすぎ注意**。
線がはっきり見えると安っぽくなるので、**ぼかしを強めに**指示してください。

### 3-C　保険：単色グラデーション（絶対に失敗しない）

```
a smooth dark navy to charcoal vertical gradient backdrop, completely
empty, seamless studio background, no people, no text, no logos,
soft top-down light falloff, subtle film grain, 16:9
```

**狙い**：3-A / 3-B がうまく出ない場合の逃げ道。
**地味ですが、人物が最も見やすく、大画面投影に一番強い**のはこれです。
迷ったらこれで構いません。

### 3-D　#4 ループ用（背景に動きをつける）

`08_loop.mp4` はフリー質問中に**流しっぱなし**になります。完全な静止画だと
「止まっている＝壊れた？」と見えるので、**ごくわずかに動かします**。

```
same dark navy corporate studio background, extremely slow drifting
bokeh lights, very subtle ambient motion only, no people, no text,
no logos, seamless loop, calm, shallow depth of field, 16:9
```

> ⚠️ **動きは「言われないと気づかない」レベルに抑えてください。**
> 背景が動くと人物の口の動きから注意が逸れます。

## 4. 8/20 の撮影指示（ここがルックの本体）

**プロンプトでは変えられない部分です。8/20に決まってしまうので、事前に共有してください。**

### 4-1　服装（本人へのお願い）

| | 指定 |
|---|---|
| ✅ 推奨 | **濃紺またはチャコールの無地スーツ**／**無地の白〜淡色シャツ**／**無地または大柄のネクタイ** |
| ❌ 避ける | **細かいストライプ・チェック**（画面でモアレが出て、ちらつきます） |
| ❌ 避ける | **緑系の服**（背景を差し替えるとき、服まで透けることがあります） |
| ❌ 避ける | 真っ白のシャツ単体（照明で白飛びしやすい） |

> 💡 **9/1当日に着る服と近いものにしてもらう**と、会場の本人と映像の差が小さくなり、
> #3のクイズがより効きます。

### 4-2　撮影条件

- **背景は無地の壁**（白・グレー）。差し替え前提なので、余計なものを映さない
- **顔に均一に光を当てる。**逆光にしない（[`SERVICE_SETUP.md` §2-3](SERVICE_SETUP.md)）
- **カメラは目線の高さ・正面・バストアップ**（胸から上）
- **同じ1回の撮影で全部撮る。**日をまたぐと光と服が変わり、ルックが揃わなくなります

**✅ 7本すべてが、この1回の撮影から作られます**

## 5. HeyGenでの適用手順

1. 動画を作る前に、生成した背景画像を **HeyGen にアップロード**
   （Create Video → 背景（Background）→ Upload）
2. **アバターの配置とサイズを決める**
   - 画面の**中央〜やや左**、**胸から上**
   - 一度決めたら**以降6本すべてで同じ配置**にする
3. **1本目を書き出し、大画面で確認**してから残りを作る
   - 会場のプロジェクタは手元のPCより**暗く・コントラストが低く**出ます
   - 背景が明るすぎて人物が沈んでいないか、ここで必ず判断する
4. 残り6本を**同じ設定のまま**書き出す

> 💡 A/Bはスライドになったので、**動画どうしの見た目の差は答えに影響しません。**
> それでも揃えるのは、単に映像として気持ちよく見せるためです。

## 8. ★A/Bスライドの体裁（#3クイズ）

**ここで答えが漏れないかどうかが決まります。**

### レイアウト

- **16:9。A と B を左右に並べる**（縦長の回答なら上下でもよい）
- **枠・背景・フォント・文字色・文字サイズをすべて同一**にする
- 背景はアバター動画と同系の**濃紺**にすると、映像との統一感が出る
- ラベル「**A**」「**B**」は同じ大きさ・同じ色・同じ位置

### 文字

- **太めのゴシック**。**画面の高さの5%以上**（200人の会場・後方席から読めること）
- **1つの回答は2文以内・60字程度**に収める
  → 長いと読み切れず、投票の判断ができません

### 🚨 答えが漏れる典型パターン（すべて潰す）

| 漏れる原因 | 対策 |
|---|---|
| **文字数が違う**（AIだけ長い／短い） | **±20%以内に揃える**。長すぎる方を削る |
| **行数が違う**（片方だけ3行） | 改行位置を調整して**見た目の行数を揃える** |
| **表記の癖が違う**（読点の多さ、「〜ですね」の有無） | 音読して違和感のある方を直す。**内容は変えない** |
| 片方だけ体言止め／片方だけ丁寧語 | **文体を揃える** |
| AIが毎回同じ側にいる | **問ごとにシャッフル**（§0-2） |

> 💡 **本人の回答は、届いた文章のままだと書き言葉になりがち**です。
> 話し言葉として自然になるよう整えてください（**内容は変えず、語尾と読点だけ**）。

### 読み上げ

- **演者がAとBの両方を読み上げます**（後方席は文字が読みにくいため）
- ★**同じトーン・同じ速度で読む。** どちらかに感情を込めると、それが手がかりになります
- 読む前に「どちらも社長の回答として読みます」と宣言しておくと、演者も自然に読めます

### A/Bスライド（5枚）

- [ ] A と B で**枠・フォント・文字サイズ・色が同一**
- [ ] **文字数が±20%以内**に揃っている
- [ ] **見た目の行数**が揃っている
- [ ] **文体・語尾・読点の癖**が揃っている
- [ ] **AIが毎回同じ側になっていない**
- [ ] AI・本物を示す表示が**どこにも入っていない**
- [ ] **後方席から文字が読める**ことを実際に確認した
